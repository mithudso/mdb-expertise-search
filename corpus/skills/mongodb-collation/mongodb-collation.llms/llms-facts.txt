# mongodb-collation — facts

> Atomic, source-anchored claims about MongoDB collation: the collation document fields, where collation is set and inherited, case-insensitive indexes, views, and gotchas.

## claims


- [fact] Collation lets MongoDB compare and order strings by language-specific rules instead of raw byte order. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/] — ../SKILL.md#overview
- [fact] The default collation is locale:"simple" (binary comparison); "Betsy" and "betsy" are different values and sort by code point out of the box. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/] — ../SKILL.md#the-collation-document
- [fact] The collation document's only required field is `locale`; every other field is optional and may carry locale-specific defaults: [asserted] — ../SKILL.md#the-collation-document
```javascript
{
  locale: <string>,          // REQUIRED (e.g. "en_US"); "simple" = binary
  caseLevel: <boolean>,      // default false
  caseFirst: <string>,       // "upper" | "lower" | "off"
  strength: <int>,           // ICU comparison level 1-5, default 3
  numericOrdering: <boolean>,// default false
  alternate: <string>,       // "non-ignorable" | "shifted"
  maxVariable: <string>,     // "punct" | "space"
  backwards: <boolean>
}
```
- [fact] [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/; MongoDB Manual: cursor.collation(), https://www.mongodb.com/docs/manual/reference/method/cursor.collation/; MongoDB Manual: Collation Locales and Default Parameters, https://www.mongodb.com/docs/manual/reference/collation-locales-defaults/] — ../SKILL.md#where-collation-is-set-and-inheritance
- [fact] Defaults consistent across locales: caseLevel:false, strength:3, numericOrdering:false, maxVariable:"punct". [cited: same three sources as the schema above] — ../SKILL.md#where-collation-is-set-and-inheritance
- [fact] Strength (the ICU comparison level) 1 ignores case and diacritics; 2 ignores case only; 3 (default) is case- and diacritic-sensitive; 4-5 add punctuation and tie-breaking distinctions. — ../SKILL.md#case-insensitive-indexes
- [fact] A strength of 1 or 2 makes a comparison case-insensitive. [cited: MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/; MongoDB Manual: cursor.collation(), https://www.mongodb.com/docs/manual/reference/method/cursor.collation/] — ../SKILL.md#case-insensitive-indexes
- [fact] caseLevel:true with strength:1 compares base characters and case; with strength:2, base characters, diacritics, and case. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/; MongoDB Manual: cursor.collation(), https://www.mongodb.com/docs/manual/reference/method/cursor.collation/] — ../SKILL.md#where-collation-is-set-and-inheritance
- [fact] numericOrdering:true compares numeric strings as numbers ("10" > "2"); the false default compares them as strings ("10" < "2"). [cited: MongoDB Manual: cursor.collation(), https://www.mongodb.com/docs/manual/reference/method/cursor.collation/] — ../SKILL.md#where-collation-is-set-and-inheritance
- [fact] Collation can be set at three levels: the collection default (at createCollection. — ../SKILL.md#case-insensitive-indexes
- [fact] all indexes and queries inherit it unless overridden), the index (can carry its own collation), and the query/sort (.collation() overrides per operation). [cited: MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/. — ../SKILL.md#case-insensitive-indexes
- [fact] MongoDB Manual: cursor.collation(), https://www.mongodb.com/docs/manual/reference/method/cursor.collation/]. — ../SKILL.md#case-insensitive-indexes
- [fact] To use a collated index for string comparisons, the operation's effective collation (explicit on the query, or inherited from the collection default when the query specifies none) must match the index's collation. — ../SKILL.md#case-insensitive-indexes
- [fact] on a collection with no default collation, an unspecified query collation falls back to "simple" and cannot use a non-simple collated index. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/. — ../SKILL.md#case-insensitive-indexes
- [fact] MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/]. — ../SKILL.md#case-insensitive-indexes
- [fact] Case-insensitivity is derived from collation: create a case-insensitive index by giving it a collation with strength 1 or 2: [asserted] — ../SKILL.md#case-insensitive-indexes
```javascript
db.names.createIndex(
  { first_name: 1 },
  { collation: { locale: "en", strength: 2 } }
)
```
- [fact] [cited: MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/] — ../SKILL.md#case-insensitive-indexes
- [fact] On a collection with no default collation, the same collation must be repeated at query level for the query to use the index. [cited: MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/] — ../SKILL.md#case-insensitive-indexes
- [fact] On a collection with a default collation, queries inherit it and use the index automatically; a different explicit query collation (e.g. strength:3) can still force a case-sensitive search. [cited: MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/] — ../SKILL.md#case-insensitive-indexes
- [fact] A view's default collation does not inherit the underlying collection's; it defaults to "simple" unless set at view creation. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/] — ../SKILL.md#collation-on-views
- [fact] String comparisons on a view use the view's own default collation and cannot be overridden per operation. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/] — ../SKILL.md#collation-on-views
- [fact] A view created from another view must match the source view's collation, and $lookup/$graphLookup across views require the views to share a collation. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/] — ../SKILL.md#collation-on-views
- [fact] An index defined with a collation, queried without it (or with a different one), is silently not used for string comparisons, causing a slow scan or case-sensitive results. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/. — ../SKILL.md#case-insensitive-indexes
- [fact] MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/]. — ../SKILL.md#case-insensitive-indexes
- [fact] The collection default does not reach a view; the view's collation must be set explicitly at creation. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/] — ../SKILL.md#collation-on-views
- [fact] A text or 2d index on a collection with a non-simple default collation needs an explicit collation:{locale:"simple"} at creation, since those index types only support simple binary comparison. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/] — ../SKILL.md#where-collation-is-set-and-inheritance
- [fact] Sorting version-like or numeric strings and getting "10" before "2" is fixed by setting numericOrdering:true. [cited: MongoDB Manual: cursor.collation(), https://www.mongodb.com/docs/manual/reference/method/cursor.collation/] — ../SKILL.md#where-collation-is-set-and-inheritance
- [fact] A case-insensitive query returning case-sensitive results means no collation was set on the query, or it differs from the index/collection collation; add .collation({locale:..., strength:2}). [cited: MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/] — ../SKILL.md#case-insensitive-indexes
- [fact] A query ignoring a case-insensitive index means the operation's collation does not match the index's collation. [cited: MongoDB Manual: Case-Insensitive Indexes, https://www.mongodb.com/docs/manual/core/index-case-insensitive/] — ../SKILL.md#case-insensitive-indexes
- [fact] A $lookup between views that errors on collation means the joined views do not share one. [cited: MongoDB Manual: Collation, https://www.mongodb.com/docs/manual/reference/collation/] — ../SKILL.md#collation-on-views
- [fact] For the full optimize-and-verify loop on a specific collated query (explain-verified rewrite + index recommendation), use an explain-verified MQL optimizer. [asserted — cross-reference, not a Manual citation] — ../SKILL.md#troubleshooting
